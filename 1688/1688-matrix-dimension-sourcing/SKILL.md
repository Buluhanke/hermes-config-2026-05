# 1688 尺寸找品（矩阵式尺寸专用）

## 何时用本技能
用户要在 1688 找带精确尺寸的商品（如 `8*8*9cm 纸盒`、`9*9*10cm 纸箱`），尤其方底盒/彩盒定制类。本技能补全通用 1688 搜索技能（1688-search-cn-gb-region-skill）**漏掉的关键坑**：尺寸是矩阵式写的，连写核对器整类漏检。

## 八大铁律（实战踩坑）

### 1. 矩阵式尺寸是头号漏检（最致命）
1688 部分商品（彩盒定制/方底盒）**不写连写 `8*8*9cm`**，而是拆成两个 SKU 选择轴：
- 长宽轴：`3x3（长宽） 4x4（长宽） … 8x8（长宽） 9x9（长宽） …`
- 高轴：`3cm（高） 4cm（高） … 9cm（高） 10cm（高） …`
任意 `长宽` × `高` = 一个真实 SKU（如 `8x8（长宽）` + `9cm（高）` = **8×8×9cm**）。

只匹配连写 `L*W*H` 的核对器（如 verify_carton.js）在这里 `skuHit=false`，**整类卖家被判"无此尺寸"**——这是误报"没货"的头号原因。

### 2. 全角括号坑（矩阵高度识别失败根因）
高度写法 `9cm（高）` 里 `（` 是**全角开括号 U+FF08**，不是闭括号 `）`。
高度正则必须 `[（）()]*`（开+闭都放行），否则 `hSet` 恒空 → `matrixHit` 恒 false。
写正则一律避免反斜杠（write_file 会双写 → 语义错），用 `[0-9]` 代替 `\d`、`[ ]` 代替 `\s`。

### 3. 直接尺寸词搜不到矩阵卖家（搜索端漏检）
`8*8*9cm纸盒` / `8*8*9cm包装盒` 关键词**排不进矩阵式卖家**——他们只在 `彩盒定制` 搜索池里（GBK 编码：`%B2%CA%BA%D0%B6%A8%D6%C6`）。
只搜直接尺寸词 → 得出"没有"的假结论。
**正确**：搜 `尺寸词纸盒` **AND** 搜 `彩盒定制`，两池求并，再逐页验矩阵尺寸。8×8×9 与 9×9×10 的江浙沪现货全部来自 `彩盒定制` 池。

### 4. 内联超长 ID 列表让 osascript 静默崩溃
把 195 个 ID 写成 AppleScript `set ids to {...}` 内联列表 → 跑一半 exit 1、输出文件 0 字节。
**修复**：ID 落纯文本文件，AppleScript 用 `paragraphs of (read (POSIX file IDFILE) as «class utf8»)` 读入循环。

### 5. extract_ids.js 的输出不能直接当 ID 喂给 verifier
`extract_ids.js` 每行是 `关键词\t{搜索结果json}`，含整页 JSON。必须先用 python 解析出纯数字 ID（9–14 位）写干净文件，再喂 verifier。

### 6. 用户已给具体链接 → 先验 TA 的线索，别从零狂扫
用户甩来的商品链接往往已是正确答案。正确顺序：
① 立即用矩阵核对器验用户给的链接 → ② 若命中，仅做**小批量补充扫描**（如 `彩盒定制` 池几十家）挖同款竞品 → ③ 不盲目扩到 200+ 页。
狂扫 200 页只为"验证用户已经给对的答案"是过度劳动，用户会烦（"跑那么久，很困难吗？"）。

### 7. 搜索端点与编码（与通用技能一致）
- 端点：`s.1688.com/selloffer/offer_search.htm`（非 `s/1688search`）
- 关键词 GBK 编码（非 UTF-8）：纸盒=`%D6%BD%BA%D0`，包装盒=`%B0%FC%D7%B0%BA%D0`，彩盒定制=`%B2%CA%BA%D0%B6%A8%D6%C6`
- 江浙沪 province：`%E6%B1%9F%E8%8B%8F,%E6%B5%99%E6%B1%9F,%E4%B8%8A%E6%B5%BD`
- 真实登录 Chrome + AppleScript `execute javascript` 驱动；JS 一律写成独立 `.js` 文件读入（内联正则会被转义吞掉，坑16）

### 8. 矩阵页价格提取
`price_clean3.js` 按连写尺寸定位，在矩阵页 `skuCount=0`（定位失败）。取价改读页面价格区，或用 `matrix_price.js` 定位 `8x8（长宽）;9cm（高）` 所在行抓单价+库存。单价可信，阶梯价需点进详情或问客服。

## 标准工作流
1. 构造两个搜索 URL（尺寸词 + 彩盒定制），江浙沪 province，翻 1–3 页，滚动懒加载，用 `extract_ids.js` 抓 offerId。
2. python 解析纯数字 ID → 干净文件。
3. `verify_carton_matrix.js`（注入 `window.TARGET='L*W*H'`）逐页验，结果 `printf >>` 追加到文件（勿内联 ID 列表）。
4. 命中 `matrixHit=true` 即含该尺寸矩阵组合。
5. 抠价用 `matrix_price.js`。

## 已验证结果（江浙沪，2026-08-21）
- **8×8×9cm**：3 家（均矩阵式）—— 677701816838 义乌盒骏、783582821059 / 786814474290 温州瀚拓；单价 ¥0.05–0.06/个，1 个起批。
- **9×9×10cm**：4 家 —— 677701816838 义乌盒骏、782048534122 / 783582821059 / 786814474290 温州瀚拓。
- 这批卖家做全尺寸组合（长宽 3–10、高 3–22 任意配），8×8×9 与 9×9×10 是同一批货源。

## 支持脚本（与本技能同目录，复制到工作区即用）
- `scripts/verify_carton_matrix.js` — 矩阵式尺寸核对器（连写 + 长宽×高 双匹配，全角括号兼容）
- `scripts/matrix_price.js` — 矩阵页精确定位 `LxL（长宽）;Hcm（高）` 行抓单价库存
- `scripts/extract_ids.js` — 搜索主列表 offerId 提取（输出 `关键词\t{json}`，需 python 后处理）

> 注：以上脚本已存在于用户技能 1688-search-cn-gb-region-skill 的 scripts/ 下。若本技能运行环境没有，从那里复制或重新生成（逻辑见上文坑2/坑8）。
