## 完整审计命令 (复制可用)

```bash
# 1. npm 全局 MCP (最快)
echo "=== npm -g MCP/related ==="
npm list -g --depth=0 2>/dev/null | grep -iE "mcp|@modelcontext" || echo "(none)"

# 2. pip 全局 MCP / SDK
echo "=== pip MCP/SDK ==="
pip3 list 2>/dev/null | grep -iE "^mcp|^fastmcp|skills-mcp" || echo "(none)"

# 3. Hermes 实际启用的
echo "=== Hermes mcp_servers: ==="
grep -A 20 '^mcp_servers:' ~/.hermes/config.yaml

# 4. 验证"我编的包名" 是不是真在 registry
for pkg in @modelcontextprotocol/server-filesystem \
           @modelcontextprotocol/server-fetch \
           mcp-server-git \
           mcp-chrome-bridge; do
  v=$(npm view "$pkg" version 2>/dev/null)
  if [ -n "$v" ]; then
    echo "✅ $pkg: $v (real package)"
  else
    echo "❌ $pkg: NOT IN REGISTRY (likely made-up name)"
  fi
done
```

## 经验教训 (供未来 audit 复用)

1. **被安全闸 BLOCKED 不要逃到训练数据** — 训练数据里的"常见包名"经常是编的。要么 `process`/`browser`/其他工具继续查, 要么**老实说"被拦了, 等你确认"**, 不许编。

2. **npm 装了 ≠ Hermes 能用** — 必须 `mcp_servers:` 段有配置才算, 框架不扫全局 npm。

3. **包名不确定必须 `npm view` 验证** — `mcp-server-fetch` 我说的时候没验证, 后来查不是真名, 浪费用户一次往返。

4. **SDK ≠ Server** — Python 的 `mcp`/`fastmcp` 是给开发者写 MCP server 用的工具, 不是给 Hermes 调用的 server, **别加进 `mcp_servers:`**。

5. **同名/同前缀要分清** — `mcp-chrome-bridge` vs `mcp-chrome-bridger` (一个 1.0.31 一个 1.0.22), 看起来像 fork, 实际不知道谁是谁, **装之前 `npm view` 看 description**。
