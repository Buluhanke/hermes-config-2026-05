# QQ Bot 行为边界与用户预期管理

## 核心问题：用户认为 QQ 机器人"记忆错乱"

**现象：** 用户在 QQ 上连续发了几条消息告诉机器人一个 API key，机器人每次回复相同的建议/方案，不"记住"之前已经收到过 key，也不去执行配置。用户觉得机器人"傻了"或"记忆错乱"。

## 真实原因

### 1. QQ Bot 每条消息独立处理（无跨消息记忆）

Hermes Gateway 的 QQ 适配器（WebSocket 到 `wss://api.sgroup.qq.com/websocket`）**每一条入站消息都触发一次独立的 LLM 调用**。除了当前会话窗口里刚刚发生的几条消息（由 LLM 的 context window 保留），QQ 机器人无法：

- 记住用户**上一轮**发过什么如果不是在同一轮请求中
- 记住用户**之前**已经提供过某个 key
- 区分用户是"第一次问"还是"又重复了一次"

所以如果用户连续发：
```
消息1: "联网搜索配置起来，key是 YOUR_API_KEY"
→ 机器人回复 1478 字（各种推荐方案）

消息2: "不要那么复杂，联网搜索是不是配置好了 key是 YOUR_API_KEY"
→ 机器人回复 277 字（又推荐一遍，更短）

消息3: "免费方案有这几个..."
→ 机器人回复 1453 字（又是推荐）
```

**每次都是独立的 LLM 请求，没有"记忆"机制说"哦，之前已经收到过 key 了"。**

### 2. QQ Bot 只能回复文字，不能执行系统操作

这是用户最大的误解点。QQ 机器人**不能**：

- 向 `.env` 文件写入 API key
- 修改 `config.yaml`
- 重启 gateway
- 执行终端命令
- 调用系统工具（如 `write_file`、`terminal`）

它本质上是一个**对话 AI**，用户发文字 → LLM 生成文字回复。所有系统操作必须通过：
- **CLI**（本机终端）
- **Dashboard Web UI**
- **SSH**（远程）

### 3. 用户的预期错位

用户把 QQ 机器人当作了一个能执行操作的**助手**，但 QQ 机器人只是一个**对话界面**。正确的流程应该是：

```
错误流程（用户以为的）：
QQ: "给你 key YOUR_API_KEY" → 机器人自动配好

正确流程：
QQ: "给你 key YOUR_API_KEY"
机器人回答 "已收到，请通过 CLI 写入 .env"
→ 用户切换到终端，让 CLI 助手写入 key
→ CLI 助手执行 write_file + gateway restart
→ 配置生效
```

## 诊断清单

当用户抱怨 QQ 机器人"傻了 / 记忆错乱 / 在绕圈子"时，按以下顺序排查：

### 第一步：区分渠道能力

| 能力 | CLI 终端 | QQ/微信 | Dashboard |
|------|----------|---------|-----------|
| 对话回答 | ✅ | ✅ | ✅ |
| 写 .env/config | ✅ | ❌ | ✅ |
| 执行命令 | ✅ | ❌ | ✅（部分） |
| 网关重启 | ✅ | ❌ | ✅ |
| 跨消息记忆 | ✅（会话内） | ❌（单条） | ✅（会话内） |

### 第二步：从日志看实际发生了什么

```bash
# 查 QQ 机器人接收的消息（注意：每条都是独立 inbound）
grep "inbound message.*platform=qqbot" ~/.hermes/logs/gateway.log | tail -10

# 查每条消息的响应
grep "response ready.*platform=qqbot" ~/.hermes/logs/gateway.log | tail -10
```

如果发现用户发了多条相关消息但机器人每次都返回不同的内容（或重复相同建议），说明是独立处理，不是记忆错乱。

### 第三步：确认配置是否需要用户操作

- 如果用户要通过 QQ 配置 key → 告诉用户这是 CLI 的活儿，QQ 做不到
- 如果用户发消息说"你帮我配置一下" → 机器人只能回文字方案
- 如果用户说"怎么还没好" → 说明对 QQ 机器人的能力有误解

## 用户沟通示例

> 用户："我发了key给它怎么没用？是不是傻了？"
>
> 回答："QQ机器人只能聊天回文字，不能改系统文件。你把key发给我（CLI），我帮你写进 .env 再重启网关就生效了。"

> 用户："每次问同样问题它都不记得之前说过什么"
>
> 回答："QQ每条消息都是独立处理的，它不记得上一轮说了什么。如果有连贯的事情，建议一条消息说完所有信息，或者直接来终端这边聊。"

## 新增：安全过滤误触发（2026-05-09）

**现象**：用户和 QQ 机器人在讨论"让 Hermes 拟人接管本地电脑"的话题，某条消息被安全过滤触发，回复：
> 我不能协助您进行任何可能涉及安全风险或违反法律法规的操作。拟人接管本地电脑属于严重安全违规行为，可能危及个人隐私和系统安全。

**根因**：QQ 每条消息独立判断，不结合上下文。当"拟人接管本地电脑"单独出现在一条消息中时，安全过滤系统直接触发，没有"用户正在研究桌面自动化方案"的背景信息来区分正常技术讨论和实际恶意操作。

**安全过滤触发特征**：
- 回复内容是通用安全提示（不提及具体错误如 100007/100016）
- 内容包含"安全风险"、"法律法规"、"隐私"等关键词
- 看起来像系统模板回复而非 LLM 生成的个性化内容

**与记忆错乱的区别**：

| 维度 | 记忆错乱 | 安全过滤误触发 |
|------|---------|--------------|
| 现象 | 重复回复相同建议 | 统一安全提示 |
| 原因 | 独立 LLM 调用无记忆 | 安全过滤单独触发 |
| 解决方案 | 引导到 CLI | 说明是上下文问题 |

**应对**：当用户抱怨"QQ 机器人在说安全问题/法律法规"时，解释这是安全过滤的误触发（上下文丢失），实际操作应通过 CLI/Dashboard 进行。

## 预防措施

1. **系统提示中明确"我是XX渠道的助手"** — 让用户知道这是QQ机器人不是CLI
2. **涉及配置操作时主动引导**：这个需要去终端操作，我这边只能给你方案
3. **用户连续发相关消息时**，在回复中总结并引导到下个步骤，避免重复推荐
4. **桌面自动化等高级功能**：主动告知用户这类操作必须通过 CLI/Dashboard，QQ 只能对话
