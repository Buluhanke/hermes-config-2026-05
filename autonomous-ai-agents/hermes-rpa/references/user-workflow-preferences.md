# 用户工作流偏好（2026-05-29 更新）

## 并行尝试原则

**场景**：用户说"两个都选行不"、"两个方向同时跑"

**用户期望**：不序列化执行，而是**同时推进多个方案**，谁先完成/有效就用谁

**正确做法**：
```python
# ❌ 错误：先做完A再做B（浪费等待时间）
do_A()
do_B()

# ✅ 正确：execute_code里同时写两个方向的代码
# 写一个脚本同时尝试方案A和方案B
# 或者分别执行，最后对比结果
```

**原因**：序列化执行是"我决定顺序"，并行是"让结果决定顺序"。后者更快、更尊重用户时间。

---

## 执行优先原则

**场景**：用户说"去试试"、"你直接弄"、"我不想听了直接做"

**用户期望**：直接执行，不事先汇报方案、不讨论风险

**正确做法**：
- 用户说"装"、"去试试"、"开始" → 直接跑命令
- 只有需要**用户做选择题**时才停下来问
- 汇报只说结果，不说过程

**触发词**：
- "你选" / "你自己决定" / "直接弄"
- "我不想听你分析了，直接做"
- "先做起来再说"

---

## 汇报格式

**用户讨厌**：长篇分析、架构图、对比表、详细过程描述

**用户喜欢**：
- 结论先行（一句话说清楚）
- 短句，不刷屏
- 口语化，像同事汇报工作

**正确示例**：
```
找到了3家纸箱供应商，价格5.2/5.5/5.8元/个。建议第2家。需要我先联系询价吗？
```

**错误示例**：
```
我帮你查了一下，发现有以下三家供应商……
（此处省略200字分析）
```
