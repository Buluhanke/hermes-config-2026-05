# 订阅隐藏与隐私风险

## 核心判断

第三方订阅转换服务是链路中的完全中间人，拿到三样东西：

1. 原始订阅 URL（含 token、uid、到期时间等鉴权信息）。
2. 完整节点列表（服务器 IP、端口、加密方式、密码/UUID、SNI）。
3. 改写返回内容的能力——可注入规则、把节点地址换成自己的机器、塞广告域名分流。

第 3 点最致命：这是「信任劫持」，不只是隐私泄露。一个恶意转换器把某个节点地址悄悄换成自己的机器，节点名不变，用户测速正常、能上网，但流量全经过它。

HTTPS 救不了：TLS 只保护「设备 ↔ 转换服务器」这一段。订阅链接在服务端已经解密落到应用层日志。加密只防路上被抢，不防对面抄。

## 方案对比

| 方案 | 隐藏了什么 | 没隐藏什么 | 适用 |
| --- | --- | --- | --- |
| token 短链（如某服务的 `/sk-xxx`） | 客户端 URL 里看不到真实订阅地址和参数 | 服务端仍持有明文订阅 URL 和节点 | 只是不想在聊天/截图里暴露链接 |
| psub 类 CF Worker 反代 | 随机化节点 IP/密码后再交给公共转换后端，拿回结果再还原 | 自己部署的 Worker 仍短暂持有真实节点 | 想用公共转换后端又不想让它看到真实节点 |
| 自建 subconverter / Worker | 全部 | 无（数据只过自己的机器） | 真要隐私 |

psub 类方案要自己部署（Cloudflare Worker + KV），现成演示站不保证长期可用。

## 自建要点

- Cloudflare Worker：项目 README 有一键 Deploy 按钮，免费层足够个人用。
- 本地 Docker：`docker run -d --name subconverter -p 127.0.0.1:25500:25500 ...`——绑 `127.0.0.1` 是关键，不对外网暴露。
- 更严的做法：Tailscale / WireGuard 内网访问，不给公网任何入口。
- 关掉 `pref.ini` 里 `api_access_token` 为空时的公开访问，设 `max_connections` 防被当公共 API 刷。

## 泄露后的处理

- 换节点、切策略组不会让旧 token 失效。必须在服务商后台**重置/撤销订阅链接**，再在所有客户端删旧配置、重新导入。
- 分享截图前遮住完整订阅 URL、节点凭据、二维码、secret。
- 订阅链接按密码处理：不发公开群、不上传 GitHub、不贴在线转换站（除非是上面说的隐私方案）。
