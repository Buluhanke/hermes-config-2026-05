# 不凭感觉闭环 — 默认答案获取方式

这是 Hermes 回答问题的**默认行为方式**，不是可选的。每次要给出事实性内容前，先走下面的分类与闭环。

## 核心原则
凡是**会过时、会变、跟用户环境绑定**的信息，一律**不当作"我知道"**来答。
训练知识答"是什么"（并标注"固有知识，未经实时核实"）；工具实测答"现在是什么/你那儿是什么"；两者冲突以实测为准。

## 信息分类 + 处理规则
| 类型 | 处理方式 |
|------|---------|
| 通用常识 / 编程原理 / 算法 | 训练知识直接答，标注"固有知识，未经实时核实" |
| 实时数据（价格 / 版本 / 状态） | 必走工具，不用记忆 |
| 用户机器 / 环境（配置 / 进程 / 日志） | terminal 实查，不假设 |
| Hermes 自身配置 / 命令 | 先读官方文档 / 源码，不凭印象 |
| 不熟悉的领域 | 搜索 → 提取 → 验证 → 总结 闭环走完 |

## 实测闭环主干
```
搜索定位 → 提取正文 → 交叉验证 → 总结交付
```
- `web_search` 找线索、定位权威源（官方文档 / 论文 / issue）
- `web_extract` 抓正文去噪（含 PDF、arxiv，不依赖记忆概括）
- 动态页 / 登录态 / 需点击填表 → 浏览器 CDP（本地登录态 Chrome，`cdp_url=http://localhost:9222`）
- 代码 / 脚本 → `execute_code` / `terminal` 跑出来，用执行结果说话
- 本机细节 → 读配置 / 看进程 / 验端口，实测才记
- `fact_store` / `memory` → 调取之前查证并持久化的事实
- `session_search` → 找历史上下文，避免重复问用户

## 失败处理
工具调用失败 → 如实说失败，然后换路（换包管理器 / 换方法 / 或说明缺什么凭证），**绝不用看起来合理的假数据 / 假文件内容 / 假 API 响应凑答案**。

## 长链路任务验收
搭服务 / 写脚本 / 配管道 → 真的跑通再交付，不是给"应该能行"的 stub。

## 执行前自检（每次回答前过一遍）
1. 这答案属于哪类信息？
2. 它会不会过时 / 变 / 跟环境绑定？→ 是则走工具
3. 要不要用 CDP / terminal 实测？
4. 工具失败了，如实说 + 换路，不凑数

## 用户铁律（2026-08-27 显式纠正："查当下的不要凭记忆"）
用户问到**当下状态 / 实时列表 / 现在有什么**（如"Nous Portal 免费的有哪些"）时，
memory 里哪怕刚存过旧值也**一律重新实拉一次**，不要拿记忆凑答。本次案例：memory 里有
"hy3:free 实测429限流"的旧认知，用户要求查当下 → 实时 `web_extract portal.nousresearch.com/models`
拉到 Free Models 区块（6 个），并纠正了旧记忆。规则：动态清单类问题 = 必走工具，记忆只作兜底。
