# Multi-Perspective Consultation

## 核心思路

通常你只能用一个模型回答问题。但有些问题（架构决策、技术选型、战略方向）需要**多模型多视角**来验证——不同AI的训练数据、推理偏好、专长领域各不相同，组合起来能得到更全面的结论。

**模式**：主agent规划问题结构 → 并行 delegate_task 给 N 个子agent，每个角色不同 → 收集结果 → 合成输出

## 执行流程

### Step 1：准备问题简报

先把背景整理成一份干净的简报文件（markdown），包含：
- 核心问题 / 目标
- 当前状态 / 系统审计数据
- 已知约束（预算、时间、资源）
- 需要回答的具体问题列表（5-6个最佳）

这只简报是所有AI角色的共同输入。

### Step 2：构造角色上下文

每个子agent的任务包含两部分：
1. **角色设定**（context参数 开头）——越具体越好
2. **任务指令**（goal参数）——包含"读取简报文件→按角色视角回答→按格式输出"

角色上下文示例：
```
你是[模型名称/角色]的[专业领域]专家。
用户有一台[硬件环境]，需要在[约束条件]下做到[目标]。
你擅长[该角色特长]。请直接给出可执行建议。
```

### Step 3：并行执行

```python
# 概念结构（非可运行代码）
tasks = [
  {
    "goal": "作为[角色A]回答...",
    "context": "角色设定...",
    "toolsets": ["file", "web"]  # 根据任务需要
  },
  {
    "goal": "作为[角色B]回答...",
    "context": "角色设定...",
  },
]
results = delegate_task(tasks=tasks)  # 并行运行，最多3个
```

### Step 4：合成输出

输出结构：
- 各家共识（所有AI一致同意的）
- 各家独特见解（某个AI独有的亮点）
- 冲突点（意见分歧的地方）
- 整合建议（你作为主agent的判断）

## 角色设定技巧

高质量的角色上下文是咨询质量的关键：

| 要素 | 作用 | 示例 |
|------|------|------|
| 模型标识 | 暗示推理偏好 | "你是GPT (OpenAI)" vs "你是DeepSeek" vs "你是智谱清言" |
| 专长领域 | 约束回答方向 | "你擅长推荐全球生态和开源方案" |
| 用户场景 | 上下文锚定 | "用户在义乌做贸易，有一台Mac mini M4" |
| 约束 | 避免脱离实际 | "核心约束：免费/低成本、本地运行优先" |
| 输出要求 | 控制格式 | "请输出干货，不要分析过程" |

## 适用场景

- ✅ 技术架构决策（本地vs云端、模型选型）
- ✅ 供应商/工具选型（多维度评估）
- ✅ 战略方向（"下一步做什么"类问题）
- ✅ 复杂问题拆解（需要多方验证）
- ✅ 预算敏感型决策（验证免费方案可行性）

## 不适用场景

- ❌ 事实查询（直接搜索更高效）
- ❌ 单步执行任务（不需要多视角）
- ❌ 需要实时交互的子任务（子agent无法使用clarify）

## 常见陷阱

1. **角色太模糊**：只说"你是AI专家"不够——要指定模型、专长、用户场景
2. **任务太大**：单个子agent的context+goal不超过5000 tokens。太长就拆
3. **等待全部完成**：delegate_task是同步的，所有子agent完成才返回。合理设置toolsets减少时间
4. **忽略环境差异**：不同AI角色可能给出完全相反的方案——冲突点是精华不是bug
5. **角色同质化**：三个角色给相同context会导致雷同回答。差异化是关键
