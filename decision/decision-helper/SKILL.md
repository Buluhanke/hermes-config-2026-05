# Decision Helper

结构化决策框架，量化评估可选方案。

## 适用场景
- 供应商选择
- 方案对比
- 优先级排序
- 风险评估

## 决策流程

### 1. 明确决策目标
- 核心诉求是什么？（价格最低？交期最快？质量最稳？）
- 有哪些硬性约束？（预算上限？时间底线？）
- 决策者是谁？（自己拍板还是给建议？）

### 2. 列出评估维度
根据场景选择相关维度，常用维度库：

| 维度 | 说明 | 权重参考 |
|------|------|---------|
| 价格/成本 | 直接金钱成本 | 高 |
| 质量/可靠性 | 产品质量/服务稳定性 | 高 |
| 交期/响应速度 | 交付时间/回复速度 | 中-高 |
| 配合度/沟通 | 响应态度/灵活度 | 中 |
| 稳定性/持续性 | 长期供货能力 | 中 |
| 资质/合规 | 认证/资质完备度 | 低-中 |

### 3. 评分矩阵

创建评分表（1-5分）：

| 选项 | 价格 | 质量 | 交期 | 配合度 | 稳定性 | 加权总分 |
|------|------|------|------|--------|--------|---------|
| 供应商A | 5 | 4 | 4 | 3 | 4 | 计算 |
| 供应商B | 4 | 5 | 3 | 5 | 3 | 计算 |
| 供应商C | 3 | 3 | 5 | 4 | 5 | 计算 |

**加权总分 = Σ(得分 × 权重)**

### 4. 敏感性分析
- 如果某个维度权重提高，哪个选项会胜出？
- 最低底线是多少？（价格不能超过X，质量必须≥Y）

### 5. 决策建议

\`\`\`
推荐：[选项名]

理由：
1. [核心优势1]
2. [核心优势2]

风险点：
- [需要注意的问题]

兜底方案：
如果[该选项]出现问题，备选：[备选名]
\`\`\`

## 快速决策模板（当选项≤3时）

**选项A vs 选项B vs 选项C**

| 维度 | 权重 | A | B | C |
|------|------|---|---|---|
| 价格 | 30% | | | |
| 质量 | 30% | | | |
| 交期 | 20% | | | |
| 配合 | 20% | | | |

**结论：** 直接给出推荐，不做过多分析，尊重用户时间。

## 升级版：多AI专家问策（Multi-AI Expert Consultation）

当决策涉及技术方向选择（如系统架构、真人化路线、工具选型），且需要多角度专业意见时，先问策再决策。

### 适用场景
- 技术路线选择需要外部专家交叉验证
- 用户要求"去问问XXAI的看法"
- 多个方案优劣不明显，需要多模型讨论
- 需要给老板审阅的决策，要有多方参考意见

### 工作流

#### Step 1：系统审计（收集现状）
用 `delegate_task` 并行收集所有相关状态，输出到单一审计报告文件。

必要内容：
- 硬件配置（CPU/RAM/磁盘/OS）
- 软件栈（版本号、已安装包）
- 配置文件内容（config.yaml 关键段）
- 所有已安装的 skills 列表
- 运行中的进程/服务
- 环境变量中的 API keys 有无配置
- 历史上下文（session_search 查最近相关会话）

#### Step 2：编写问策文档
产出两个文件：
- `problem-brief.md` — 背景 + 问题 + 约束条件（预算/时间/技术栈）
- `ai-consult-prompt.md` — 各家AI看的完整prompt，含审计摘要和具体问题

问策文档的结构：
```
# 背景（给AI看）
[系统审计摘要, 2-3段]

# ✅ 已就绪
[bullet list]

# ❌ 缺口（急需解决的）
[分项列出，每项说明现状和期望]

# 💰 预算约束
[费用限制说明]

# 问题
1. [具体问题1]
2. [具体问题2]
...
```

#### Step 3：并行询问多AI
用 `delegate_task(tasks=[...])` 并行发3-5个子任务，每个扮演一个AI专家：

```python
tasks = [
    {"goal": "扮演智谱清言专家，给出...建议", "context": "...", "toolsets": ["file"]},
    {"goal": "扮演GPT专家，给出...建议", "context": "...", "toolsets": ["file"]},
    {"goal": "扮演DeepSeek专家，给出...建议", "context": "...", "toolsets": ["file"]},
]
```

每个子任务先 `read_file` 读问策文档，然后输出该AI视角的建议。

**关键点：**
- 每个AI给定不同 persona（智谱清言擅长国产方案、GPT擅长全球开源、DeepSeek擅长推理和本地部署）
- 每个AI都回答相同的问题列表
- 要求"直接出干货，不要分析过程"
- 语言必须跟用户一致（中文问题→中文回答）

#### Step 4：汇总共识
从各AI回复中提取：
- **三家AI共识**（都推荐的事—最高优先级）
- **各家AI独特见解**（各有侧重点）
- **分阶段建议对比**（合并成统一的路线图）
- **预估成本**（合并估算）

输出汇总报告，三段式：
```
## 三家AI共识
[大家都推荐的N件事，排优先级]

## 各家AI独特见解
- [AI A]: [独特角度]
- [AI B]: [独特角度]
- [AI C]: [独特角度]

## 分阶段路线图（合并版）
Phase 0 — 今天干: [具体任务+成本+时间]
Phase 1 — 本周: ...
Phase 2 — 两周内: ...
Phase 3 — 一个月内: ...
```

#### Step 5：决策与执行
根据共识和用户偏好，直接给出推荐动作：
```
推荐：先做 [动作A]（三家AI都推荐，最快见效，0成本）
可做可不做： [动作B]（有分歧，按预算决定）
不推荐： [动作C]（无人推荐，跳过）
```

### 关键教训（Pitfalls）
- **不要重复劳动**：报告文件写好后，各AI子任务用 read_file 读同一文件，不要每人发一份不同的
- **不要给选择题**：用户讨厌"选A还是B"，直接给结论"做A"
- **用户要的是结论不是过程**：最终输出三段式汇总，不要展示中间步骤
- **语言一致性**：中文用户的问题→中文回答每份报告，否则汇总时会混入英文
- **没账号别硬连**：如果用户要求去网页版各AI咨询，但没账号，用 delegate_task 模拟不同AI视角是可行的替代方案
- **注意 token 消耗**：审计报告+问策文档可能几千字，每个子任务都要读，总 token 消耗大。审计信息只写关键的，不要全量dump
