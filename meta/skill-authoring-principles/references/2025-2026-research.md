# Skill Authoring Research Notes — 2025-2026 Developments

## Anthropic Agent Skills (Oct 2025)

**Source**: https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills

**Key publication**: "Agent Skills" — organized folders of instructions, scripts, and resources that agents discover and load dynamically. Published Oct 16, 2025.

### Three-Level Progressive Disclosure (Official)

1. **L1** — name + description only: pre-loaded into system prompt at startup. Claude uses this to decide whether to load the skill.
2. **L2** — SKILL.md body: loaded when skill is relevant. Keep lean.
3. **L3** — linked files in skill directory: read as needed, unlimited. Scripts execute without loading.

> "Building a skill for an agent is like putting together an onboarding guide for a new hire."

**Skills ecosystem**: Skills are now supported across claude.ai, Claude Code, Claude Agent SDK, and Claude Developer Platform. An open standard (agentskills.io) enables cross-platform portability (Dec 2025).

**Future direction**: Agents that create, edit, and evaluate Skills on their own — codifying their own patterns of behavior into reusable capabilities.

## Anthropic Skill Authoring Best Practices

**Source**: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices

### Core Principles

**1. Concise is key**
Context window is a shared resource. Only add context Claude genuinely lacks. Challenge every paragraph: Does Claude really need this explanation? Does this justify its token cost?

**Good (~50 tokens)**:
```markdown
## Extract PDF text
Use pdfplumber: `with pdfplumber.open("file.pdf") as pdf: text = pdf.pages[0].extract_text()`
```

**Bad (~150 tokens)**: Explanations of what PDFs are, library installation, etc.

**2. Degrees of Freedom** (NEW framework)

Match instruction specificity to task fragility:

| Level | Use when | Example |
|---|---|---|
| High freedom | Multiple valid approaches, context drives choice | "Review code for bugs" |
| Medium freedom | Preferred pattern exists, some variation OK | `generate_report(data, format="markdown")` |
| Low freedom | Fragile, sequence-dependent, consistency-critical | Exact migration script, no modifications |

Analogy: narrow bridge with cliffs → low freedom (precise guardrails). Open field → high freedom (trust the model).

**3. Test across all target models**
Haiku needs more guidance than Opus. If using across models, aim for instructions that work for all.

## OTel + eBPF Zero-Code Instrumentation (Nov 2025)

**Source**: https://opentelemetry.io/blog/2025/obi-announcing-first-release/

**Breakthrough**: OpenTelemetry eBPF Instrumentation (OBI) released Nov 2025. Instruments every application in a cluster — Go, Java, Python, Node.js, Ruby — without touching a single line of code.

**Key capabilities**:
- Automatic protocol detection (HTTP, gRPC, database, messaging)
- No code changes or restarts required
- 10x faster test execution vs previous instrumentation
- Zero-code distributed tracing across services

**Practical workflow**: Deploy OBI collector → automatically instruments all pods → traces flow without any per-service configuration.

**Grafana Beyla**: Grafana Labs donated its eBPF auto-instrumentation tool (Beyla) to OpenTelemetry. Now part of the official OBI project.

## Ponytail — AI Coding Agent Governance

**Source**: https://betterstack.com/community/guides/ai/ponytail-ai/

### The Problem
AI coding agents default to: solve the right problem in the *most complex way possible*. They generate wrappers, over-abstract, add dependencies for problems already solved by the standard library.

### The Solution: Six-Rung Decision Ladder

Before writing any code, evaluate in order:

1. Does this need to exist at all? (YAGNI — if not, skip)
2. Does the standard library handle it? → use it
3. Does a native platform feature handle it? → use it
4. Does an already-installed dependency handle it? → use it
5. Can it be solved in one line? → write one line
6. Only then: write minimum custom code that works

**Key constraint**: Minimalism applies to *complexity and dependencies*, not correctness, safety, security, or accessibility. Trust-boundary validation and data-loss handling are never skippable.

### Benchmark Results
- 77-94% code reduction across 5 LLMs on 5 tasks
- 20% cost reduction in Claude Code Pro usage

### 2026 Updates
- Native `<dialog>` element for modals (HTML5 built-in, with focus trapping + backdrop)
- sed for config changes vs Python subprocess for YAML edits (use the simplest tool)
- Plugin ecosystem: ponytail is now a real Claude Code plugin, not just methodology
