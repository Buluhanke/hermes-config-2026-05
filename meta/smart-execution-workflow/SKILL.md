# Smart Execution Workflow — 智能执行工作流

## 核心理念

**社区优先搜索 + 主动执行落地 = 最高效的工作流**

每次技术任务，先花5-10分钟搜索社区最佳实践，然后立即动手执行，避免重复造轮子。

## 工作流程 (5步机械执行)

### 步骤1: 社区搜索 (5分钟)
```
执行社区搜索：
1. 检查Hermes官方社区 (Discord/GitHub/文档)
2. 搜索AI/Agent生态社区
3. 查找Stack Overflow/Reddit等技术论坛
4. 评估找到方案的质量
```

**搜索关键词模板**：
- 安装类: `site:github.com "hermes skill" + [工具名] + "best practice"`
- 代码类: `site:github.com "hermes" + [功能需求] + "implementation"`
- 配置类: `site:hermes-agent.nousresearch.com/docs [配置项] + "example"`

### 步骤2: 方案评估 (2分钟)
```
质量评估清单：
✅ Star数 > 100 (社区验证)
✅ 最近更新 < 6个月 (维护活跃)
✅ 有完整文档 (使用门槛低)
✅ issue解决率高 (维护者响应积极)
✅ 有成功案例 (有人实际用过)
```

### 步骤3: 立即动手执行 (不等待)
```
如果找到优质方案 → 直接采用
如果没找到 → 按Ponytail决策梯子最小化实现
```

### 步骤4: 验证结果 (必须)
```
三重验证：
1. ARTIFACT 真实存在 (ls/grep验证)
2. fact_store INSERT 一条记录 (COMMIT + read back)
3. 通知发送 exit_code=0 + delivery handle
```

### 步骤5: 记录经验 (立即)
```
写入memory：
- 成功方案：记录社区链接和最佳实践
- 失败案例：记录坑点和替代方案
- 新发现：记录可复用的技巧
```

## 失败案例记录

### Failure 67: 重复造轮子 (2026-07-05)
**现象**: 用户强调"重新安装skill和需要添加代码一定要先在hermes几大社区或论坛搜索查找有没有现成的更好的更优的可以借鉴的"
**根因**: 没有建立社区搜索习惯，直接动手写代码/安装
**修法**: 建立5步智能执行工作流，强制社区搜索+立即执行

### Failure 68: 流程嘴炮 (2026-07-05)
**现象**: 任务标完成但fact_store无记录，通知未发送
**根因**: 只完成ARTIFACT，跳过fact_store和通知验证
**修法**: 强化步骤4三重验证，缺一项都不算完成

## Ponytail决策梯子集成

在步骤2评估和步骤3执行时，结合Ponytail哲学：

```
1. 这东西真的需要存在吗？(YAGNI)
   → 社区搜索后确认无现成方案
   
2. 标准库已经做了？用标准库
   → 搜索Hermes内置工具和技能
   
3. 平台/系统原生功能覆盖？用原生的
   → 搜索操作系统原生方案
   
4. 已装的依赖能解决？用现成的
   → 搜索已安装工具的插件/扩展
   
5. 能写成一行？写成一行
   → 搜索简洁的最佳实践
   
6. 写完才：最小能 work 的代码
   → 社区验证最小实现
```

## 关键原则

### ✅ 做什么
- **先搜索后执行**: 5-10分钟社区搜索，避免重复造轮子
- **立即动手**: 找到方案后立即执行，不拖延
- **三重验证**: ARTIFACT + fact_store + 通知，缺一不可
- **记录经验**: 每次任务后立即写入memory

### ❌ 不做什么
- **不要重复造轮子**: 90%的问题社区已有解答
- **不要只说不做**: 搜索后必须立即执行
- **不要跳过验证**: 完成必须有三重证据
- **不要空等下次**: 经验必须立即记录
