# MEMORY.md 夜间学习块模板集

**使用场景**: 每次 cron（夜间学习 / 早上复盘 / 周末压缩 / 异常事故）触发「总结 24h → 写入 MEMORY.md」时，挑一个模板套。

**插入位置**: `## [关键词索引]` 之后、最新日期块之前（**倒序**）。不要 append 到文件末尾。

**⚠️ cron 会话写 MEMORY.md 只能用 patch 工具**（memory tool 不可用）。

**统一格式**:
```markdown
## [YYYY-MM-DD <时段>] <一句话主题>
- **关键经验 (N条)**: ...
- **fact_store**: 起始→结束 (+N 条), 主题分布 = A + B
- **核心落地动作**: 1. ... 2. ... 3. ...
- **下次轮次关注**: ...
- **新写入 fact_store 主题**: 1. ... 2. ...
```

## 模板 A：标准夜间学习（21:00 或 01:00 cron）

适合：fact_store 24h 有 ≥5 条新增、ai_collector 跑成功。

```markdown
## [2026-06-29 夜间学习] <一句话主题，如 "GUI agent + 安全纵深">
- **关键经验 (N条)**: <3-5 条核心洞察，每条不超过 1 行>
- **fact_store**: 87→107 (+20 条)，新增主题分布 = GUI grounding 6 + 安全注入 4 + 决策梯/工具链 4 + Ollama 2 + misc 4
- **核心落地动作**:
  1. <具体可执行项 1>
  2. <具体可执行项 2>
  3. <具体可执行项 3>
  4. <具体可执行项 4>
- **下次轮次关注**: <下一步要验证/补的事>
- **新写入 fact_store 主题**:
  1. <主题1> (trust=N, 状态: 已落地/待落地)
  2. <主题2>
  3. <主题3>
  4. <主题4>
```

**字数**: 300-500 字（用户说 200 字时砍「下次轮次关注」+「新写入 fact_store 主题」两节）

## 模板 B：自学 cron 失败 / 0 新增（应急）

适合：ai_collector.log 报 "DeepSeek tab not found"、fact_store 24h = 0 条。

```markdown
## [2026-06-29 夜间学习] 自学 cron 异常 - 0 新增
- **异常**: ai_collector 01:00 跑失败（DeepSeek tab not found, 第 N 次连续），新增 fact=0
- **根因**: <从 agent.log 看到真实原因，如 Chrome 9222 端口冲突 / 网络断>
- **手动补救**: 21:00 补跑 ask_ai_sites.py，新增 N 条（topic1, topic2, ...）
- **下次轮次关注**: 修 Chrome debug 端口 / 加 retry 逻辑
- **MEMORY.md 状态**: 字数 N（超 14KB 才触发压缩）
```

**关键**: **不要写"今天没学习"**——session_search 能找到真实活动记录。从 agent.log / SOUL.md 修改时间戳 / config.yaml 变化都算学习证据。

## 模板 C：异常事故复盘

适合：系统挂了 / 内存爆了 / 关键 cron 跑炸了。

```markdown
## [2026-06-29 夜间学习] ⚠️ <事故名，如 "memory 飙到 92% watchdog 自动卸载 LLaVA">
- **时间线**:
  - HH:MM 触发: <事件>
  - HH:MM 升级: <状态>
  - HH:MM 解决: <动作 + 效果>
- **根因**: <5-Why 分析，至少追到可避免的设计缺陷>
- **修复**:
  1. 立即: <热修>
  2. 中期: <配置/代码变更>
  3. 长期: <架构调整>
- **预防**: <下次怎么不再犯，如加 monitor / 改阈值 / 加 retry>
- **写入 fact_store**: 主题="<事故名 + 教训>" trust=0.85
```

## 模板 D：周末压缩 / 回顾（周日 03:00 cron）

适合：周报型 cron，把过去 7 天的「夜间学习」块合并成一周回顾。

```markdown
## [2026-06-22 ~ 2026-06-28 周回顾] <一句话主题>
- **本周新增 fact**: N 条（high-trust X 条 / mid Y 条 / low Z 条）
- **核心主题**: <3-5 个反复出现的主题，如 GUI grounding / 安全注入 / cron 静默 / 本地模型>
- **已落地**:
  1. <item1>
  2. <item2>
- **未落地 / 推下周**:
  1. <item1>
  2. <item2>
- **下周 focus**: <1-2 个最重要的方向>
- **MEMORY.md 状态**: 字数 N（≤15KB 健康，>15KB 合并旧块）
- **被合并的旧块**: [06-22] [06-23] [06-24] [06-25] [06-26] [06-27] 夜间学习 → 本块
```

**操作**: patch 写完周回顾块后，**再 patch 删掉被合并的 6 个旧块**——腾出字数预算。

## 模板 E：极简版（用户硬要 200 字以内 + 不展开）

适合：用户明确说 "不超过 200 字" / "直接完成" / "不要展开" / 紧急汇报。

```markdown
## [YYYY-MM-DD <时段>] <一句话主题>
- **关键经验 (3条)**: <最核心 3 条，每条 ≤30 字>
- **fact_store**: X→Y (+N 条)
- **落地动作**: 1. ... 2. ... 3. ...
```

**字数**: ≤200 字。砍掉所有「下次轮次关注」/「新写入 fact_store 主题」子节。

**关键**: 用户说"直接完成"时 — 查 session_search 找到学习证据 → 挑最重要的 3-5 条各一行 → 用 patch 写入 daily_learning log → 完成。不停在"我该写什么"。

## 块插入的 patch 模式

```python
# 找到「## [关键词索引]」这一行的位置，在它后面插新块
old = """## [关键词索引]
- 意图反查 (task-completion-confirm)"""

new = """## [YYYY-MM-DD 夜间学习] <主题>
- ...

## [关键词索引]
- 意图反查 (task-completion-confirm)"""
```

**不要**用 `echo "..." >> ~/.hermes/MEMORY.md`——破坏倒序。

## 字数与压缩（2026-07-02 实测校正）

- ~~软上限 2200 字~~ → **真实上限 ~14KB**（实测 14KB/11 节仍正常）
- **真正瓶颈是信噪比**，不是字节数
- 判断标准: `wc -c ~/.hermes/MEMORY.md` > 14KB 才触发合并
- 压缩时**优先合并相邻 2-3 天**为周回顾（模板 D），而不是直接砍
- 容量检测: `wc -c ~/.hermes/MEMORY.md`（比 `wc -m` 更稳定）
