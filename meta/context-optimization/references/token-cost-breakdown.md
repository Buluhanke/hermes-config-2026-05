## 固定开销解剖（~13.9K tokens/call）

每次 API 调用，在发送用户消息之前就已经消耗了 ~13.9K tokens：

| 组件 | Token 量 | 占比 | 优化手段 |
|------|----------|------|----------|
| 工具定义 | 8K–10K | ~57-72% | 禁用不用的工具、工具门控 |
| 系统提示 | 2K–3K | ~14-22% | 精简 SOUL.md |
| 记忆文件 | 1K–5K | ~7-36% | MEMORY.md <2200 字符 |
| 活跃技能 | 0–2K | 0-14% | 按需加载（渐进式披露） |
| 上下文 | 变量 | 变量 | /compress 压缩 |

## 优化效果估算

### 基准（未优化）
- 每轮输入：~13.9K tokens
- 月费用（重度用户 ~1000 轮/天）：~$40

### 优化后
- 禁用 5 个不常用工具：-2K tokens
- MEMORY.md 压缩到 1500 字符：-500 tokens
- 工具门控（lazy loading）：-1K tokens
- 每轮输入：~10.4K tokens
- 月费用（重度用户）：~$4-8

## 关键洞察
- **工具定义是最大的开销** — 禁用不用的工具效果最显著
- **记忆文件膨胀是隐形杀手** — 人类编辑的记忆倾向于增长，定期清理
- **技能按需加载** — 渐进式披露是 Hermes 的 token 优化核心机制
- **模型路由** — routine 任务用便宜模型，复杂任务用贵模型，是最直接的省钱方式
