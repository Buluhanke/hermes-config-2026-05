# 任务状态追踪 SOP (v1.6.0 落地)

## 三层防护体系

### 1️⃣ 任务文件追踪 (文件系统级)

**目录结构**:
```
~/.hermes/tasks/
├── archive/                     # 历史看门狗报告
│   └── watchdog-report-*.md
└── done/                        # 已完成任务归档
    ├── 20260625_090015.md
    └── 20260625_120033.md
# 进行中任务临时出现在根目录中，完成后立即归档到 done/
```

**任务文件格式**:
```markdown
---
任务：[任务描述]
状态：进行中/完成/失败
创建时间：2026-06-25 HH:MM
更新时间：2026-06-25 HH:MM
步骤：
- [x] 步骤 1（已完成）
- [ ] 步骤 2（待执行）
结果：[完成后填写]
---
```

**使用规则**:
1. **收到任务立即创建文件** - 不创建=违规
2. **每步完成后更新状态** - 打勾 + 更新时间
3. **全部完成后标记 DONE** - 推送到 Telegram
4. **gateway 重启先检查 tasks/** - 有未完成的继续执行
5. **看门狗每 15 分钟检查** - 停滞>30 分钟告警

### 2️⃣ USER.md v3.0 执行铁律 (文档级)

**6 条铁律** (违反=系统故障):
1. 说「我会去做」= 立即执行，不是下次
2. 说「已完成」= 必须有截图或终端输出作为证据
3. 说「下一步」= 立即执行下一步，不等回复
4. 遇到障碍 = 换方法继续，不是停下来问
5. 任务未完成时 gateway 重启 = 重启后第一件事是继续任务
6. 违反以上任何一条 = 系统故障，需要自我修复

**触发词**: 「帮我做 X」「去做 X」「执行 X」→ 0 思考立即开始，创建任务文件，按步骤执行到底

### 3️⃣ 看门狗监控 (cron 级)

**cron 配置**:
```yaml
name: task-watchdog
schedule: "*/15 * * * *"
description: 每 15 分钟检查未完成任务
prompt: |
  检查任务状态：
  1. 扫描 ~/.hermes/tasks/ 目录
  2. 找出所有状态为"进行中"超过 30 分钟的任务
  3. 如果 gateway 正常运行但任务还在进行中，推送 Telegram 告知用户
  4. 如果发现任务文件存在但没有进展，自动重新执行该任务
  5. 完成的任务归档到 ~/.hermes/tasks/done/
```

**cron ID**: `ec6677e2b987` (2026-06-25 创建)

## 完整执行流程

### 阶段 1: 任务接收
```
用户指令 → 创建任务文件 → 拆解步骤 → 写入文件 → 执行步骤 1
```

### 阶段 2: 执行中
```
每完成一步 → 更新任务文件 (打勾 + 时间) → 继续下一步
```

### 阶段 3: 完成
```
所有步骤完成 → 验证结果 (截图/终端输出) → 标记 DONE → 推送 Telegram → 归档到 done/
```

### 阶段 4: 重启恢复
```
gateway 重启 → 扫描 tasks/ → 找到"进行中"文件 → 继续执行 → 更新状态
```

## 量化指标

**完成定义** (必须全部满足):
- ✅ 所有步骤打勾
- ✅ 结果字段已填写
- ✅ 有截图或终端输出作为证据
- ✅ Telegram 汇报已推送
- ✅ 文件标记为"完成"

**停滞定义**:
- 任务文件存在
- 状态="进行中"
- 最后修改时间 > 30 分钟前
- 看门狗推送 Telegram 告警

## 违规检测

**忘记创建任务文件**:
- 用户问"任务状态呢？"
- 看门狗扫描不到对应文件
- → 立即创建 + 补足步骤

**说好但没做**:
- 说"已完成"但没有截图/输出
- 任务文件步骤未打勾
- → 立即补执行 + 补证据

**做了一半停下**:
- 步骤 1 打勾，步骤 2 未碰
- 超过 30 分钟无更新
- → 看门狗告警 → 继续执行

**重启后丢失任务**:
- gateway 重启后没检查 tasks/
- → 触发自我修复机制 → 立即扫描 + 继续
