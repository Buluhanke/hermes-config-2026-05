# 1688 详情页价格/起批量提取（实战可用）

## 坑位与修法
1. **中文直接回传必乱码（根因 + 修法）**
   - 现象：AppleScript `execute javascript "..."` 把返回值当 MacRoman/UTF-8 混处理，中文全变 `??`/乱码，连累价格、标题、起批量（`¥0`/`起订:个`/`title乱码`）。
   - 修法：JS 端先把中文转成 `\uXXXX` ASCII 串再回传：
     ```js
     const esc = s => (s == null ? '' : String(s)).replace(/[^\x00-\x7F]/g,
       c => '\u' + c.charCodeAt(0).toString(16).padStart(4, '0'));
     return esc(JSON.stringify({...}));
     ```
   - 本机解码（Python）：
     ```python
     import json
     d = json.loads(payload.encode('utf-8').decode('unicode_escape'))
     ```
   - 布尔/数字字段不受此影响，但凡含中文一律走 ASCII 通道。

2. **正则里的 `/` 必须转义**
   - `/\d+\.\d+\s*(元|/|起)/` 在 JS 里是 SyntaxError（未转义的 `/` 被当正则结束符）。写成 `元|\/|起` 即 `元|\/|起`。

3. **SKU 价格区有两种布局（坑21，最关键的提取坑）**
   - 1688 详情页价格不在主价区（主价是活动占位/默认尺寸价）。真实单价在 `.module-od-sku-selection` 内，分两种形态：
     - **布局A（inline）**：尺寸与价同行连写，如 `16*16*16cm ¥0.65 库存12345个`。正则直接抠：
       `(\d[\d.]*\s*[*\u00d7xX]\s*\d[\d.]*\s*[*\u00d7xX]\s*\d[\d.]*\s*(cm|CM)?)\s*\u00a5\s*([\d.]+)\s*\u5e93\u5b58\s*([\d,]+)`
     - **布局B（size-bar）**：尺寸是选择条按钮（如 `16*16*16cm`），价默认显示**第一个尺寸**，目标尺寸不选中时无价。必须 `chip.click()` 选中目标尺寸后再读 `.item-price-stock` 的 `¥x.xx / 库存N个`。
     - **退路**：两种都拿不到时，取首个 `.item-price-stock`（多为默认选中=目标尺寸，如 `634987797003` 默认选中即 16*16*16）。
   - 已固化脚本：`scripts/price_clean3.js`（首选，兼容 A+B+退路）。`price_clean2.js` 仅拿锚点价，弃用。

4. **规格命中必须是真实 SKU，不是广告文案（坑20，最致命假阳性）**
   - 正文/标题含 `16*16*16cm` ≠ 该尺寸在售。案例：`751990874462`（义乌圣天新材料）正文含 16*16*16，但 SKU 实际只有 `15*15*15 / 17.5*17.5*17.5` 等 21 个尺寸，**无 16*16*16**——旧 `verify_carton.js` 用 `body.innerText` 正则误判为真纸箱。
   - 修法：`verify_carton.js` 规格命中**唯一权威 = 真实 SKU 尺寸集合**（从 `.module-od-sku-selection` 抽 `\d*\d*\d*cm` 建集合，正方形底面加 L*W...H cm(高) 拆写兜底），目标尺寸归一化(去 .0) 后必须在集合内才 `skuHit=true`。
   - 复验 5 个原命中：4 个真有 16*16*16 通过，1 个误中正确剔除。

5. **起批量抓取**
   - 主价区正则：`/(\d+)\s*(?:个|件|只|套|PCS|pcs)\s*起批/`
   - 注意单位不统一（件/个/箱/PCS），别硬转。
