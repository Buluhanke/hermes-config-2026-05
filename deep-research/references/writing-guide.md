# 写作指南

## 报告格式

```markdown
# [研究标题]

**摘要**
[2–4 句话概括核心发现；直接说结论，不要说"本报告将探讨……"]

---

## 目录
（主章节 ≥ 3 个时必须提供，列出所有一级和二级标题）
- [一、章节标题](#)
  - [子节标题](#)
  ...

---

## 一、[章节标题]

### [子节标题]
[内容，织入引用脚注如 [^1][^2]]

...

## 结论
[直接回答核心研究问题。若用户要求评估、推荐或预测，必须给出明确判断，不能只罗列信息而不表态]

---

## 参考文献
[^1]: 标题 — URL
[^2]: 标题 — URL
...
```

---

## 起草时的写作要求

**内容层面**

- **来源铁律**：所有数据、案例、结论必须来自已爬取的参考资料，禁止凭空生成
- **反幻觉规则**：涉及具体数字（市场规模、排名、时间节点、人物言论）时，必须能在引用来源中找到对应原文。若搜索结果中无法验证某数据点，宁可写"公开数据有限"也不要编造。**尤其禁止虚构未来事件的具体数据**
- **跨来源综合**：优秀的见解来自**多个来源的交叉验证和模式识别**，而不是逐条摘录。每个主章节至少综合 3 个不同来源。
- **定量问题必须给数字**：用户问题中含"比重是多少"、"年用量是多少"等明确数量要求的，报告必须给出具体数值或合理估计区间（含推算依据）。"数据有限"不是答案——即便是估算，也要写出"基于X推算，约为Y，误差±Z%"。
- **维度语义忠实**：用户命名的每个维度，按字面语义理解，不得偷换。遇到模糊维度，在章节首句说明理解方式。
- **预测要有数量级与时间节点**：趋势预测不能只用"将增长"，需给出具体时间节点和数量级。
- **数据时效性**：引用超过 2 年的核心市场数据需标注获取年份。
- **批判性分析**：对主要论点，不只说"有效"，还要说明：在什么条件下适用、有哪些已知局限。
  - 弱："XYZ 策略已被证明有效。"
  - 强："XYZ 策略效果量 d=0.8，但主要证据来自北美环境；国内实施时忠诚度下降约 40%，核心原因是教师培训资源不足。"
- **覆盖广度原则**：
  - 策略类：不只列"是什么"，必须覆盖"如何实施"（个性化选择、关键条件、实施支持机制）
  - 市场/政策类：核心分析前必须有宏观背景铺垫（政策走向、经济驱动力、监管框架）
  - 比较分析类：每个实体覆盖所有用户指定的比较维度；信息不足时写"公开信息有限"而非跳过
  - 学术框架类：每个理论视角有独立实质性讨论，不得合并为泛化的"多元视角"
- **洞察密度**：每个主章节应有至少 1 条**跨来源推断性结论**：
  - **对比洞察**：两组数据差异背后揭示的深层原因
  - **推演洞察**：从已知事实推断出的隐性结论
  - **结构化重组**：用新框架整合碎片信息（为框架命名）
  - **因果链**：把相互影响的因素串成箭头链条
- **机制分析**：对每个关键结论，不只说"是什么"，要说清"为什么"。
  - 弱："ALD 因其共形性而被选用。"
  - 强："ALD 的共形性源于其自限制的表面化学反应——每个 ALD 半循环只在暴露的悬挂键上发生单层反应，深宽比大于 10:1 的孔洞内部也能均匀覆盖。"
- **结论有态度**：遇到"哪家公司最值得关注"、"哪个方向最有前景"，结论必须给出明确判断。

**多实体比较的一致性模板**

- **统一子标题结构**：每个实体的介绍段落使用完全相同的子标题顺序
- **用户指定的比较维度 = 子标题**：直接用作每个实体的子标题，保持原措辞
- **汇总表格**：N ≥ 3 个实体时，优先在章节末尾加一张汇总对比表

**表达层面**

- **受众适配**：
  - 所有缩写首次出现必须写全称 + 括号内中文说明
  - 面向普通读者：每个抽象概念配具体例子，每个建议说明如何落地
  - 面向专业读者：精准术语为主，数据和方案比理论更重要
  - **受众不确定时默认为"普通读者"模式**
- **入门引导节**：正文第一个核心章节之前，必须有"背景与基本概念"节（≥300字）
- **多项对比用表格**：凡涉及多方案、公司、方法的横向比较，优先用对比表格
- **全景总览表**：涉及多方法/策略/技术梳理时，在详细分析前先用汇总表列出所有主要选项
- **Mermaid 图表**：流程、依赖关系、时间线优先用 Mermaid 呈现
- **合成型报告**：趋势提炼优先于清单枚举，每个趋势选 2-3 个最典型案例
- **技术类报告缩写集中导引**：当报告密集使用专业缩写（≥5 个），在目录后加缩写导引表
- **不重复**：后续章节不复述前章已有内容；同一 URL 只出现一次
- **段落长度控制**：单段 ≤200 字；一段只讲一个话题；列表项超过 5 条时改用表格
- **摘要写法**：首句直接给出最重要结论（含具体数字），不用"本报告将探讨…"开头

**引用格式**
- 正文中用 `[^1]`、`[^2]` 标注，文末统一列出
- 只记录实际读取过全文的来源

**篇幅参考**：6000 字以上，多维度、多比较对象的课题不设上限

## 起草后：修订检查

> ⚠️ **重点优先保证**：洞察密度、批判性视角、定量数据、结论表态、指令遵循

| 检查项 | 常见问题 |
|--------|---------|
| 报告类型与格式是否对应？ | 合成型课题是否在"提炼趋势"而不在"枚举清单" |
| 用户每个问号有没有直接回答？ | 扫描用户原始提问中的每个"？" |
| 定量问题有没有给数字？ | 用户问"比重是多少"，是否给了具体数值或估计区间 |
| 并列子问题深度是否均衡？ | 最多/最少覆盖比是否 ≤ 2:1 |
| 领域标准类别覆盖率是否 ≥80%？ | 对照阶段 1c 清单 |
| 市场/政策类是否有宏观背景节？ | 核心分析前是否建立了宏观环境框架 |
| 策略类是否有实施支持层？ | 是否覆盖了"如何实施"层 |
| 学术框架类是否逐维度独立展开？ | 用户要求的每个理论视角是否独立子节 |
| 比较分析每个实体维度是否完整？ | 空白格应填"信息有限"而非留空 |
| 预测是否有数量级和时间节点？ | 是否包含具体年份和数量级 |
| 数据时效性是否注明？ | 超过2年的核心数据是否标注了获取时间 |
| 洞察密度是否足够？ | 每个主章节是否有 ≥1 条跨来源推断性结论 |
| 摘要数字与正文计算是否一致？ | 摘要给出估算数字，正文推算必须能得出同一区间 |
| 有没有虚构的具体数据？ | 检查所有具体数字是否都有来源 |
| 篇幅是否达标？ | 正文是否 ≥6000 字 |
| 全景总览表是否存在？ | 涉及多方法/策略梳理时是否在详细分析前有汇总表 |
