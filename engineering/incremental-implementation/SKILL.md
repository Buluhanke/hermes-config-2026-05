# Incremental Implementation

## Overview

大任务拆成小步骤，每步完成前可测试、可回滚、可部署。**永远不在未测试的代码上继续添加功能**。

核心原则：
1. 每步都是有意义的最小完整功能
2. 每步完成后立即验证（不只是编译通过）
3. 每步都有可用的产出，不只是"中间状态"
4. 任何时候都能回滚到上一个稳定点

## When to Use

- 任何预计超过2小时的任务
- 任何涉及超过3个文件改动的任务
- 任何涉及数据库迁移的任务
- 任何涉及API接口变更的任务
- 团队协作时，任何需要合并代码的场景

## Process

### Step 1: 定义完整范围

#### 1.1 写出最终目标
- 用一句话描述最终产出
- 明确什么叫"完成"
- 定义验收标准（可测试的）

#### 1.2 识别依赖关系
- 哪些是前置依赖（必须先完成）？
- 哪些可以并行开发？
- 哪些有外部依赖（第三方API、人）？

#### 1.3 划分边界
- 明确本任务的范围（做什么）
- 明确排除的范围（不做什么）
- 识别潜在的陷阱（容易出错的地方）

### Step 2: 拆解成1-2小时的小步

#### 2.1 列出所有步骤
- 每个步骤都是一个"有意义的小功能"
- 每个步骤完成后系统仍然可用
- 每个步骤的产物可以独立演示

#### 2.2 排序
- 依赖顺序在前
- 风险高的步骤早发现早处理
- 核心功能在前，边缘功能在后

#### 2.3 每步定义检查点
- 本步完成的标准是什么？
- 如何验证本步正确性？
- 本步可能引入什么风险？

### Step 3: 执行每个小步

#### 3.1 实施前检查
- 当前代码已通过所有测试
- 了解本步要改什么
- 准备好回滚方案

#### 3.2 实施中
- 只做本步必要的改动
- 不为"未来可能需要"提前优化
- 及时commit（不要等到最后一起commit）

#### 3.3 实施后验证
- 运行本步相关的所有测试
- 手动验证核心功能
- 检查是否有新的警告

### Step 4: 集成与回归

#### 4.1 每步集成
- 合并到主分支或测试分支
- 运行完整测试套件
- 观察CI/CD状态

#### 4.2 回归测试
- 运行所有端到端测试
- 检查监控和日志
- 确认无性能倒退

## Common Rationalizations

| 常见借口 | 真相 | 反制 |
|---------|------|------|
| "这次功能太多，必须一次性完成" | 大爆炸式开发必然导致难以调试的中间状态 | 至少拆成每天可部署的粒度 |
| "小步太琐碎，影响效率" | 事后debug和回滚比小步开发更费时 | 记录每次小步节省的debug时间 |
| "我已经有完整的方案，不需要逐步验证" | 再完整的方案也有没想到的细节 | 小步验证能发现方案漏洞 |
| "测试环境可以随便改，生产再说" | 测试环境的经验不能外推到生产 | 保持测试和生产环境一致 |
| "先把功能完成，再补测试" | 功能完成后往往没有动力补测试 | TDD本身就是增量 |

## Red Flags

- 改动超过5个文件没有分步
- 预计任务时间超过1周没有分解
- 任何无法在30分钟内回滚的改动
- 任何人说"这个先这样，以后再改"
- 合并请求超过500行diff
- 没有测试覆盖的新功能

## Verification

验证清单：

- [ ] 任务已分解成≤2小时的子任务
- [ ] 每个子任务有明确的完成标准
- [ ] 每个子任务有对应的测试或验证方式
- [ ] 任意时刻可以回滚到上一个稳定点
- [ ] 集成后运行了完整测试套件
- [ ] 改动已部署到预生产环境验证
- [ ] 相关文档已更新

## 本 session 补充：批量写文件后的增量验证模式

大规模代码迁移/重构时（如跨目录迁移整个项目结构），推荐以下节奏：

```
1. 创建目录结构（mkdir，只创建空目录）
2. 写 requirements.txt / setup.py / 基础 __init__.py
3. 验证：python3 -c "import package"  ✓
4. 逐模块迁移代码（每写一个模块立即 import + 实例化验证）
5. 验证：python3 tests/test_all.py  ✓
6. 最后验证 CLI 入口
```

本 session 实际节奏：
- 写了 3 个 HTML 页面（fake_site）
- 写了 `bridge.py` → `HermesPerceptionBridge()` 实例化验证
- 写了 `agent_v2/web_agent_v2.py` → UCB1 + WorldGraph 逻辑验证
- 写了 `agent_v3/modules.py` → 反复遇到 `AgentV3Modules` 不存在、`SkillLibrary(data_dir=...)` 参数不匹配 → 修复后再测
- 写了 `start.py` → `--help` 验证
- 最终 `python3 tests/test_all.py` → 8/8 通过

教训：**每个新类写完后立即实例化验证**，不要等所有文件都写完再一次性测试。越早发现接口不匹配，修复成本越低。
